# RÚBRICA DEL EVENTO (escala 1 a 4 por criterio)

Antes de entregar cualquier cosa, revisa contra esto y dime qué puntaje sacaría y qué falta para llegar a 4.

## 1. Systems design — 30% (cierra 12:00)
- **Entendimiento del problema** → 4 = nombra supuestos, casos difíciles y lo que deja fuera, con razones. (1 = repite el brief sin decidir)
- **Arquitectura y trade-offs** → 4 = cada decisión dice qué alternativa descartó y por qué. (1 = diagrama sin decisiones)
- **Plan para medir** → 4 = casos de prueba y métricas concretas desde el diseño. (1 = no hay forma de medir)

## 2. Ejecución — 40% (cierra 20:00)
- **Resultado en el set oculto** → 4 = resuelve la mayoría de casos, incluidos los nuevos.
- **Respuesta al incidente** → 4 = detecta el cambio, se adapta y lo explica.
- **Calidad del repo** → 4 = corre siguiendo el README y el código se explica solo.

## 3. Demo day — 15%
- **Claridad** → 4 = en minutos queda claro el problema, la solución y la evidencia.
- **Evidencia** → 4 = resultados reales, incluido lo que no salió.

## 4. Profundidad técnica — 15% (debrief)
- **Explicación de decisiones** → 4 = explica fallas, límites y qué haría después.
- **Lectura de resultados** → 4 = explica cada falla con una causa concreta.

## Reglas del evento que afectan la nota
- Presupuesto de la llave: US$50 (US$5 bloqueados para el debrief). Cuidar el gasto.
- La API debe cumplir el contrato EXACTO del brief.
- Habrá un incidente a mitad del día (algo cambia).
- Los organizadores evalúan lo que se entrega, despliega y explica.
